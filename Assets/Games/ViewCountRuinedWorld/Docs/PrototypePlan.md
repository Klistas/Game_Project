# 조회수 때문에 세계가 망함 - 재미검증 프로토타입 계획

## 정체성

플레이어는 악성 루머 스트리머다. 매일 `대상 카드 + 주장 카드 + 조건/효과 카드` 3장을 조합해 쇼츠를 올리고, 조회수와 믿음 확산으로 마을의 규칙을 망가뜨려 7일 안에 선택한 병맛 엔딩을 달성한다.

핵심 재미는 전투력이 아니라 "사회 규칙이 바뀌는 카드 조합"에서 나온다.

## 현재 프로젝트 적용 원칙

- 원문 지시서는 Godot 4.6.x, GDScript, Steam PC MVP를 기준으로 한다.
- 현재 Unity 통합 프로젝트에서는 재미검증용 독립 프로토타입으로만 만든다.
- 데이터와 규칙은 JSON/ScriptableObject 교체가 쉬운 구조로 두고, UI/연출과 시뮬레이션 로직을 분리한다.
- 추후 상업화 판단 시 `Godot 원안`, `독립 Unity 프로젝트`, `현재 Unity에서 분리` 중 하나로 재결정한다.
- 이 폴더 밖의 다른 게임 에셋/씬/스크립트를 참조하지 않는다.

## MVP 고정 범위

- 엔딩 3종: 고양이 대통령 당선, 바나나 정부 수립, 시장님 문어화.
- 7일 제한 런.
- 카드 54장 목표: 대상 18, 주장 18, 조건/효과 18.
- NPC 타입 8개.
- 상태값 12개 중 프로토타입 화면에서는 선택 엔딩 관련 3개를 크게 표시한다.
- 쇼츠 업로드는 영상 편집이 아니라 카드 조합 결과, 제목 후보, 썸네일 톤, 예상 조회수/신고 위험을 보여주는 화면으로 처리한다.
- 자유 입력, 실존 인물/현실 정치 소재, 멀티플레이, 모바일, 3D 오픈월드는 제외한다.

## 첫 플레이어블 목표

1. 목표 엔딩을 하나 선택한다.
2. 하루마다 카드 3장을 고른다.
3. 조합 결과로 루머 제목과 예상 수치가 나온다.
4. 업로드하면 조회수, 신뢰도, 신고 위험, NPC 믿음이 변한다.
5. 하루 종료 리포트로 "왜 이렇게 됐는지"를 보여준다.
6. 7일 내 조건을 만족하면 성공 엔딩, 실패하면 실패 리포트를 보여준다.

첫 빌드는 아트 완성보다 "조합이 웃긴가", "결과가 납득되는가", "한 번 더 해보고 싶은가"를 우선 검증한다.

## 프로토타입 화면 구성

| 화면 | 목적 | 필수 상호작용 |
| --- | --- | --- |
| 타이틀 | 게임 정체성 전달 | 새 게임 시작 |
| 목표 선택 | 이번 런 방향 고정 | 3개 엔딩 중 선택 |
| 마을 관찰 | 현재 상태와 활성 루머 확인 | 카드 선택으로 이동 |
| 카드 선택 | 대상/주장/조건 조합 | 카드 3장 선택, 예상 결과 미리보기 |
| 쇼츠 업로드 | 조회수 상승 쾌감 | 제목/썸네일 톤 선택, 업로드 |
| NPC 반응 피드 | 루머 확산 피드백 | 댓글/리믹스/반박 표시 |
| 하루 리포트 | 원인과 결과 정리 | 다음 날 진행 |
| 팩트체크 경고 | 리스크 관리 | 경고 확인, 위험 수치 표시 |
| 엔딩 | 런 보상 | 성공/실패 원인 표시, 재시작 |

## 구현 순서

### Phase 0. 격리와 기준선

- `Assets/Games/ViewCountRuinedWorld` 아래에만 자료를 둔다.
- 원본 기획서와 지시서를 `Docs`에 복사한다.
- 콘셉트아트와 임시 레퍼런스를 `Art/References`에 둔다.
- 다른 게임의 씬, 리소스, 네임스페이스를 참조하지 않는다.

### Phase 1. 데이터 기반 코어

- CardData, RumorData, TownState, EndingCondition 데이터 모델 작성.
- 카드 ID, 타입, 태그, 수치 참조 검증기 작성.
- RumorComposer: 카드 3장으로 루머 생성.
- UploadSimulator: 조회수, 공유, 신고, 신뢰도 변화 계산.
- BeliefSimulator: NPC 타입별 믿음 확산.
- EndingEvaluator: 3개 엔딩 성공/실패 판정.

### Phase 2. 7일 런 연결

- RunController로 하루 시작, 카드 선택, 업로드, 리포트, 다음 날 흐름을 연결한다.
- 테스트 모드에서 각 엔딩을 강제로 달성할 수 있게 한다.
- UI 없이도 7일 자동 시뮬레이션이 가능해야 한다.

### Phase 3. 플레이 가능한 UI

- 카드 선택, 쇼츠 업로드, 마을 상태, 하루 리포트, 엔딩 화면을 하나의 씬에 연결한다.
- 초기에는 placeholder 카드/아이콘으로 진행한다.
- 숫자 변화와 병맛 문장을 크게 보여준다.

### Phase 4. 콘텐츠 1차

- GDD의 20개 루머 예시를 먼저 입력한다.
- 이후 54장 카드, 15개 부작용, 15개 충돌로 확장한다.
- 모든 콘텐츠는 데이터 검증을 통과해야 한다.

### Phase 5. 아트/연출 적용

- 레퍼런스의 "스트리머 + 도시 + 쇼츠 UI + 병맛 사회 붕괴" 톤을 적용한다.
- Title, KeyVisual, Thumbnail은 메뉴/로딩/상점용으로 분리한다.
- 카드 아이콘, NPC 초상, 마을 구역 배경은 교체 가능한 슬롯으로 둔다.

### Phase 6. 재미 검증

- 외부 플레이어 5명 이상에게 15~25분 런을 플레이시킨다.
- 첫 웃음이 10분 안에 나오는지 확인한다.
- 카드 조합 -> 결과 -> 엔딩 조건 관계를 설명 없이 이해하는지 확인한다.
- 3런 안에 최소 한 번 엔딩에 도달 가능한지 확인한다.

## 검증 기준

- 플레이어가 "내 카드 선택 때문에 마을이 이상해졌다"고 느낀다.
- 결과가 70%는 예측 가능하고 30%는 웃긴 방향으로 비틀린다.
- 실패해도 "다음에는 다른 조합을 해보자"는 동기가 생긴다.
- 엔딩 3종 모두 테스트 모드와 일반 플레이에서 볼 수 있다.
- 카드/상태/엔딩 수치가 하드코딩되지 않는다.
