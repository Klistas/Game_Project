# 조회수 때문에 세계가 망함 - Codex 실행용 프로젝트 브리프

## 0. 한 줄 피치
가짜뉴스 쇼츠를 올렸더니 NPC들이 믿기 시작하고, 믿는 사람이 많아질수록 그 소문이 마을 법칙이 되는 병맛 사회 시뮬 로그라이크.

## 1. 개발 목표
- 1인 개발자가 8~12주 안에 Steam PC용 MVP 데모를 만들 수 있는 범위로 고정한다.
- 완전 자유 입력이 아니라 대상/주장/조건 카드 3장 조합으로만 소문을 만든다.
- 핵심 재미는 `카드 조합 -> 쇼츠 업로드 -> NPC 믿음 확산 -> 마을 규칙 변화 -> 부작용/충돌 -> 7일 엔딩 판정`이다.
- 현실 정치, 실존 인물, 실제 뉴스, 현실 허위정보 사건은 직접 다루지 않는다.

## 2. MVP 고정 범위
| 항목 | 범위 |
|---|---:|
| 엔딩 | 3개: 고양이 대통령 당선, 바나나 정부 수립, 시장님 문어화 |
| 소문 카드 | 54장 권장: 대상 18, 주장 18, 조건/효과 18 |
| NPC 타입 | 8개: 일반 주민, 학생, 경찰, 상인, 공무원, 기자, 팩트체커, 고양이 |
| 마을 구역 | 5개: 광장, 편의점 거리, 학교 앞, 관공서, 방송국 골목 |
| 믿음 단계 | 4단계: 의심, 유행, 상식, 법칙 |
| 런 구조 | 7일 제한, 1런 15~25분 |
| 부작용 | 15개 이상 |
| 충돌 이벤트 | 15~20개 |
| 제외 | 온라인 멀티, 자유 입력, 무한 절차 생성, 복잡한 경제, 3D 오픈월드 |

## 3. 선택 기술 스택
- 엔진: Godot 4.6.x stable 권장, RC/베타 버전은 사용 금지
- 언어: GDScript 우선. C#은 MVP에서 금지한다.
- 데이터: CSV/JSON 또는 Godot Resource 중 하나로 시작하되, Codex 작업 편의성을 위해 초기는 JSON/CSV 권장.
- UI: Godot Control 노드 기반.
- 카메라/맵: 2D 쿼터뷰처럼 보이는 고정 미니 마을.
- 테스트: 외부 의존성 최소화. 자체 `tools/test_runner.gd`와 데이터 검증 스크립트부터 만든다.

## 4. 절대 바꾸면 안 되는 핵심 규칙
1. AI나 Codex가 게임 규칙을 자유 생성하지 않는다.
2. 모든 결과는 카드 ID, 태그, 수치, 상태값, 이벤트 테이블로 결정한다.
3. AI 생성 문구는 표현 보조이며 밸런스와 엔딩 조건을 바꾸지 않는다.
4. 현실 정치/실존 인물/실제 뉴스 패러디를 넣지 않는다.
5. 새로운 기능은 반드시 MVP 범위표에 먼저 들어가야 한다.
6. 플레이어가 업로드 전에 예상 결과를 어느 정도 읽을 수 있어야 한다.
7. 실패는 코미디여야 하며, 억까가 아니라 원인-결과로 설명되어야 한다.

## 5. 재미 검증 목표
- 첫 웃음: 튜토리얼 시작 후 3분 이내.
- 첫 이해: “소문이 법칙이 된다”를 5분 이내 이해.
- 첫 원인 감각: 1일차 종료 전에 “내 소문 때문에 NPC 행동이 바뀌었다” 경험.
- 1런 클립성: 15~25분 안에 공유하고 싶은 장면 3개 이상.
- 실패 만족도: 실패해도 결과 리포트가 웃기고 재도전 동기가 남아야 함.

# AGENTS.md - Codex 작업 지시서

이 저장소에서 작업하는 Codex 에이전트는 아래 규칙을 따른다.

## 1. 프로젝트 정체성
- 게임명 가제: 조회수 때문에 세계가 망함
- 장르: 싱글 사회 시뮬레이션 + 로그라이크 + 카드 조합 + 병맛 전략 게임
- 핵심 루프: 목표 엔딩 선택 -> 7일 동안 소문 제작 -> 믿음 확산 -> 마을 법칙 변화 -> 부작용/충돌 -> 엔딩 판정
- MVP 목표: Steam PC용 플레이 가능한 데모

## 2. 작업 방식
- 한 번에 하나의 티켓만 수행한다.
- 작업 전 `docs/PROJECT_BRIEF.md`, `docs/TECHNICAL_ARCHITECTURE.md`, `docs/DEVELOPMENT_PIPELINE.md`를 읽는다.
- 변경 전 짧은 구현 계획을 작성한다.
- 변경 후 반드시 테스트/검증 결과를 요약한다.
- 실패한 테스트가 있으면 숨기지 말고 원인과 다음 조치를 적는다.
- 대규모 리팩터링은 별도 티켓 없이는 하지 않는다.

## 3. 금지 사항
- 현실 정치, 실존 인물, 실제 뉴스 사건, 실제 허위정보 사례를 콘텐츠에 넣지 않는다.
- 자유 입력형 소문 시스템을 만들지 않는다.
- 엔딩 조건을 임의로 바꾸지 않는다.
- 밸런스 수치를 하드코딩하지 않는다. 데이터 테이블에서 읽는다.
- 새 플러그인/패키지/엔진 버전 변경은 사람 승인 없이 하지 않는다.
- 멀티플레이, 모바일, 3D 오픈월드, 복잡한 경제 시뮬레이션은 MVP에서 구현하지 않는다.

## 4. 코드 원칙
- 시뮬레이션 로직과 UI를 분리한다.
- 핵심 시스템은 가능한 한 순수 함수에 가깝게 작성한다.
- 데이터 검증을 먼저 만들고, 콘텐츠 추가 때마다 검증한다.
- 모든 ID는 소문/카드/상태값/이벤트 테이블에서 참조 가능해야 한다.
- 매직 넘버를 피하고 `BalanceConfig` 또는 데이터 파일로 이동한다.

## 6. Definition of Done
각 티켓은 다음을 만족해야 완료다.
- 기능이 MVP 범위와 일치한다.
- 관련 데이터/테스트가 추가되었다.
- 수동 검증 절차가 문서화되었다.
- UI 작업이면 최소 플레이 가능한 화면 흐름이 유지된다.
- 새 콘텐츠는 현실 이슈 금지 규칙을 통과한다.
- 다음 티켓에서 이어받을 수 있도록 변경 요약이 명확하다.

# 기술 설계서 - 조회수 때문에 세계가 망함

## 1. 아키텍처 목표
이 프로젝트는 “병맛 콘텐츠가 많아 보이지만 내부는 단순한 데이터 기반 시뮬레이션”이어야 한다.

```text
CardData
-> RumorData
-> UploadResult
-> GroupBeliefData
-> TownState
-> SideEffectResult
-> ConflictResult
-> EndingCheck
```

## 2. 주요 모듈
| 모듈 | 책임 | UI와 분리 여부 |
|---|---|---|
| CardRepository | 카드 데이터 로드/검증 | 완전 분리 |
| RumorComposer | 3장 카드 조합으로 Rumor 생성 | 완전 분리 |
| UploadSimulator | 자극도/신뢰도/조회수/신고 수 계산 | 완전 분리 |
| BeliefSimulator | NPC 타입별 믿음 점수와 단계 계산 | 완전 분리 |
| TownStateService | 12개 마을 상태값 증감 | 완전 분리 |
| SideEffectResolver | 부작용 후보 선정과 적용 | 완전 분리 |
| ConflictResolver | 동시에 퍼진 소문 간 충돌 판정 | 완전 분리 |
| EndingEvaluator | 3개 엔딩 조건 판정 | 완전 분리 |
| RunController | 7일 흐름과 저장/리포트 연결 | 부분 분리 |
| UIController | 화면 전환, 패널 표시, 입력 처리 | UI 전용 |

## 3. 핵심 데이터 모델

### CardData
```json
{
  "id": "target_banana",
  "type": "target",
  "name_ko": "바나나",
  "rarity": "common",
  "tags": ["banana", "object", "economy"],
  "base_sensational": 4,
  "base_credibility": 2,
  "target_groups": ["resident", "merchant", "police"],
  "unlock": "start"
}
```

### RumorData
```json
{
  "id": "rumor_target_banana_claim_id_effect_arrest",
  "card_ids": ["target_banana", "claim_is_id", "effect_arrest_without"],
  "tags": ["banana", "identity", "law", "police"],
  "sensational": 8,
  "credibility": 4,
  "factcheck_risk": 6,
  "stage": "doubt"
}
```

### TownState
필수 상태값은 아래 12개로 고정한다.

| 상태값 ID | 한국어명 | 범위 | 설명 |
|---|---|---:|---|
| chaos | 혼란도 | 0~100 | 전체 변칙 상황 |
| trust | 신뢰도 | 0~100 | 플레이어 채널 신뢰 |
| views | 조회수 | 0~999999 | 누적 조회수 |
| fatigue | 소문 피로도 | 0~100 | 반복 소문 피로 |
| institution | 기관 개입도 | 0~100 | 경찰/공무원 개입 |
| mayor_trust | 시장 신뢰도 | 0~100 | 시장 권위 |
| cat_support | 고양이 지지율 | 0~100 | 고양이 엔딩 핵심 |
| banana_power | 바나나 권력도 | 0~100 | 바나나 엔딩 핵심 |
| octopus_suspicion | 문어 의심도 | 0~100 | 문어화 엔딩 핵심 |
| economy | 경제 안정도 | 0~100 | 품절/가격/암시장 |
| anxiety | 시민 불안도 | 0~100 | 위험, 체포, 혼란 |
| factcheck | 팩트체크 압박 | 0~100 | 반박 뉴스 위험 |

## 4. 하루 처리 순서
```pseudo
start_day()
show_town_state()
draw_cards()
compose_rumor_from_3_cards()
upload_result = simulate_upload(rumor, thumbnail_tone)
apply_upload_to_views_and_reports(upload_result)
for each npc_group:
    delta = calculate_belief_delta(rumor, npc_group, town_state, upload_result)
    npc_group.belief[rumor.id] += delta
    update_belief_stage(npc_group, rumor)
update_global_rumor_stage(rumor)
apply_town_state_changes(rumor)
resolve_side_effects(rumor, town_state)
resolve_conflicts(active_rumors)
resolve_factcheck(upload_result, town_state)
create_day_report()
check_ending_or_continue()
```

## 5. 테스트 전략
| 테스트 | 목적 | 예시 |
|---|---|---|
| 데이터 검증 | 참조 오류와 금지 콘텐츠 방지 | 모든 카드 ID 중복 없음 |
| 조합 테스트 | 카드 3장 조합 결과 확인 | 바나나+신분증+체포 태그가 law 포함 |
| 확산 테스트 | 믿음 단계 상승 확인 | 믿음 75 이상이면 법칙 |
| 부작용 테스트 | 태그 기반 발생 확인 | banana+economy면 품절 후보 |
| 엔딩 테스트 | 조건 체크 정확도 | cat_support 80 이상 등 |
| 런 시뮬 테스트 | 7일 전체 흐름 검증 | 7일 종료 시 결과 리포트 생성 |

## 6. 빌드/검증 명령 예시

# 개발 파이프라인 - Codex End-to-End

## 0. 큰 전제
- 재미 검증 단계까지 진행하고, 그 결과가 괜찮다고 가정한다.
- 단, 검증 절차와 기준은 문서에 남긴다.
- 검증 통과 후에는 핵심 루프를 갈아엎지 않고 콘텐츠/연출/밸런스/출시 준비로 넘어간다.

## 1. 단계 요약
| Phase | 이름 | 목표 | 종료 조건 |
|---:|---|---|---|
| 0 | 저장소 부트스트랩 | Codex가 안전하게 작업할 뼈대 생성 | Godot 프로젝트 실행, 테스트 러너 실행 |
| 1 | 시뮬레이션 코어 | 카드/소문/업로드/믿음/상태값 계산 | UI 없이 7일 런 시뮬 가능 |
| 2 | 플레이 가능한 UI | 카드 선택부터 하루 리포트까지 연결 | 마우스로 1일 진행 가능 |
| 3 | MVP 콘텐츠 | 카드 54장, NPC 8개, 부작용 15개 | 데이터 검증 통과 |
| 4 | 엔딩 3종 | 7일 내 성공/실패 판정 | 세 엔딩 모두 테스트 가능 |
| 5 | 재미 검증 | 외부 플레이어가 훅을 이해하고 웃는지 확인 | 첫 웃음/클립성/이해도 기준 통과 |
| 6 | 데모 폴리시 | 연출, 사운드, 튜토리얼, 밸런스 | 1런 15~25분 안정화 |
| 7 | Steam 데모 준비 | 빌드, 페이지, 트레일러 소재, 버그 수정 | 데모 후보 빌드 산출 |
| 8 | 출시 이후 | 신규 카드/엔딩/멀티 설계 확장 | 업데이트 로드맵 운영 |

## 2. Phase 0 - 저장소 부트스트랩
### 목표
Codex가 안전하게 이어서 작업할 수 있는 최소 저장소를 만든다.

### 작업
- Godot 프로젝트 생성.
- `AGENTS.md`, `docs/`, `data/`, `tests/`, `tools/` 구성.
- 빈 Main 씬, UI 루트, 테스트 러너 생성.
- `.gitignore`, README, 버전 고정 문서 작성.

### 산출물
- 실행 가능한 빈 프로젝트.
- 테스트 명령 1개.
- 데이터 검증 명령 1개.

### Codex 완료 기준
- 에디터에서 프로젝트가 열림.
- Headless 테스트 러너가 0 실패로 종료.
- 이후 티켓이 참고할 문서 경로가 존재.

## 3. Phase 1 - 시뮬레이션 코어
### 목표
UI 없이도 “7일 동안 소문을 올리면 상태가 변하고 엔딩이 판정되는” 순수 코어를 만든다.

### 작업 순서
1. CardData/Repository
2. RumorComposer
3. UploadSimulator
4. NPCType/BeliefSimulator
5. TownStateService
6. SideEffectResolver
7. ConflictResolver
8. EndingEvaluator
9. RunController
10. DayReport 생성

### 종료 조건
- 테스트 코드에서 바나나 신분증 조합을 실행하면 바나나 권력도가 증가한다.
- 고양이 대통령 목표 조건이 테스트로 성공/실패 판정된다.
- 7일 자동 시뮬레이션 후 리포트가 생성된다.

## 4. Phase 2 - 플레이 가능한 UI
### 목표
시뮬레이션 코어를 사람이 클릭해서 볼 수 있게 만든다.

### 필수 화면
- 타이틀 화면
- 목표 엔딩 선택 화면
- 마을 관찰 화면
- 소문 카드 선택 화면
- 쇼츠 업로드 화면
- NPC 반응 피드
- 믿음 확산 지도
- 마을 상태 패널
- 하루 종료 리포트
- 팩트체크 경고 화면
- 엔딩 화면
- 해금 화면

### 종료 조건
- 새 게임 시작부터 7일차 엔딩까지 끊기지 않는다.
- 아트가 플레이스홀더여도 정보가 명확하다.
- 하루마다 최소 1개 이상의 시각 변화가 보인다.

## 5. Phase 3 - MVP 콘텐츠
### 목표
콘텐츠량이 적어 보이지 않도록 최소 데이터 세트를 채운다.

### 포함
- 카드 54장.
- NPC 타입 8개.
- 부작용 15개 이상.
- 충돌 이벤트 15~20개.
- 엔딩별 추천 카드/방해 요소/중간 이벤트.

### 종료 조건
- 데이터 검증 전부 통과.
- 10런 자동 시뮬레이션에서 같은 결과만 반복되지 않는다.

## 6. Phase 4 - 엔딩 3종 구현
### 목표
고양이 대통령, 바나나 정부, 시장님 문어화 엔딩을 완성한다.

### 종료 조건
- 각 엔딩을 테스트 모드에서 강제 달성할 수 있다.
- 실패 엔딩도 웃긴 리포트를 남긴다.
- 엔딩 화면에서 “왜 성공/실패했는지”가 보인다.

## 7. Phase 5 - 재미 검증
### 테스트 대상
- 개발자 본인 제외 5명 이상.
- 가능하면 게임 개발 경험 없는 사람 3명 이상.
- 가능하면 스트리머/영상 편집 감각이 있는 사람 1명 이상.

### 측정 지표
| 지표 | 통과 기준 |
|---|---|
| 첫 웃음 시간 | 3분 이내 |
| 핵심 이해 시간 | 5분 이내 |
| 1런 완료율 | 70% 이상 |
| “내가 원인” 발화 | 1런 중 2회 이상 |
| 클립 후보 장면 | 1런 중 3개 이상 |
| 재도전 의향 | 60% 이상 |

### 통과 후 결정
재미 검증이 통과했다고 가정하면, 이후에는 코어 재설계 금지. 밸런스/연출/콘텐츠 추가만 한다.

## 8. Phase 6 - 데모 폴리시
### 작업
- 튜토리얼 압축.
- 법칙화 연출 강화.
- 사운드 피드백 추가.
- 하루 리포트 가독성 개선.
- 카드/부작용 밸런스 조정.
- 옵션/저장/해금 최소 구현.

### 종료 조건
- 1런 15~25분.
- 첫 엔딩 3런 내 달성 가능.
- 실패해도 도감/해금이 남는다.

## 9. Phase 7 - Steam 데모 준비
### 작업
- Steam 태그/상점 문구.
- 캡슐 이미지 기획.
- 데모 빌드 패키징.
- 트레일러 클립 리스트.
- 버그 수정.
- 컨트롤/튜토리얼 검수.

### 종료 조건
- 외부 PC에서 새 설치 후 실행 가능.
- 세이브 초기화/재설치 문제가 없다.
- 30분 내 데모 핵심을 보여준다.

## 10. Phase 8 - 출시 이후
### 업데이트 순서
1. 신규 카드팩.
2. 신규 엔딩팩.
3. 신규 마을 구역.
4. 스트리머 채팅 투표 모드.
5. 친구끼리 루머 전쟁 모드.

### 멀티는 나중에
멀티는 MVP에 구현하지 않는다. 설계는 유지하되 실제 구현은 턴제 동시 제출 방식으로 시작한다.

# QA 및 재미 검증 계획

## 1. 검증의 목적
이 문서는 “재미 검증까지 통과한다고 가정”하더라도, 무엇을 통과했다고 볼지 명확히 하기 위한 기준이다.

## 2. 핵심 질문
1. 플레이어가 5분 안에 소문이 세계 법칙이 되는 구조를 이해하는가?
2. 첫 런 안에 “이걸 왜 NPC가 믿어?”라는 웃음이 발생하는가?
3. 플레이어가 결과를 랜덤이 아니라 자기 선택의 결과로 느끼는가?
4. 실패했을 때도 리포트가 웃긴가?
5. 스트리머가 제목으로 뽑을 만한 장면이 3개 이상 생기는가?

## 3. 플레이테스트 프로토콜
| 단계 | 내용 |
|---|---|
| 준비 | 새 세이브, 튜토리얼 켬, 녹화 가능하면 녹화 |
| 안내 | 게임 설명은 한 줄 피치만 제공 |
| 플레이 | 1런 끝까지 플레이, 개발자는 개입하지 않음 |
| 관찰 | 첫 웃음, 헷갈린 지점, 리액션 발화 기록 |
| 설문 | 5점 척도와 자유 응답 |
| 분석 | 공통 이탈 지점과 클립 후보 장면 정리 |

## 4. 정량 기준
| 지표 | 목표 |
|---|---:|
| 튜토리얼 이탈률 | 20% 이하 |
| 1런 완료율 | 70% 이상 |
| 첫 웃음 평균 시간 | 3분 이내 |
| 핵심 이해 평균 시간 | 5분 이내 |
| 1런 클립 후보 수 | 3개 이상 |
| 첫 3런 내 엔딩 성공률 | 50% 이상 |
| 재도전 의향 | 60% 이상 |

## 5. 설문 문항
- “내가 만든 소문 때문에 마을이 바뀌었다고 느꼈다.” 1~5점
- “결과가 완전 랜덤이 아니라 이해 가능했다.” 1~5점
- “실패해도 웃겼다.” 1~5점
- “다른 소문 조합을 다시 해보고 싶다.” 1~5점
- “친구/시청자에게 보여주고 싶은 장면이 있었다.” 1~5점
- 가장 웃겼던 장면은?
- 가장 이해하기 어려웠던 화면은?
- 너무 느리거나 빠르게 느껴진 순간은?

## 6. 검증 통과 후 규칙
재미 검증을 통과했다고 판단하면 아래 규칙을 적용한다.
- 코어 루프 재설계 금지.
- 카드 3장 조합 구조 유지.
- 7일 런 구조 유지.
- 엔딩 3종을 데모의 중심으로 유지.
- 이후 작업은 가독성, 연출, 밸런스, 콘텐츠 보강 위주로 제한.

# 출시 및 출시 이후 파이프라인

## 1. 데모 출시 전 체크리스트
| 항목 | 기준 |
|---|---|
| 실행 | 새 PC에서 설치 후 실행 가능 |
| 튜토리얼 | 5분 안에 핵심 루프 전달 |
| 런 길이 | 15~25분 |
| 엔딩 | 데모에서 최소 고양이 대통령 엔딩 완주 가능 |
| 실패 | 실패 엔딩과 리포트가 출력됨 |
| 성능 | 보급형 PC에서 60fps 목표, 최소 30fps 유지 |
| 콘텐츠 안전 | 현실 인물/정치/실제 뉴스 직접 언급 없음 |
| 버그 | 진행 불가 버그 0개 |
| 리포트 | 플레이 로그/밸런스 리포트 출력 가능 |

## 2. Steam 페이지 전략
| 항목 | 방향 |
|---|---|
| 태그 | Simulation, Strategy, Roguelike, Card Game, Comedy, Satire, Singleplayer, Choices Matter |
| 가격 | 정식 출시 9,900~14,900원대 권장 |
| 데모 | 고양이 대통령 엔딩 1개 완주, 나머지 2개 맛보기 |
| 트레일러 | 바나나 신분증, 고양이 투표권, 문어 시장 의심 3장면 중심 |
| 스크린샷 | 카드 조합, 쇼츠 업로드, NPC 반응, 법칙화, 엔딩 리포트 |

## 3. 출시 이후 업데이트 순서
1. 버그 수정과 밸런스 핫픽스.
2. 신규 카드팩 1: 동물/편의점 소문.
3. 신규 엔딩팩 1: 우체통 왕국, 비둘기 세무청, 신호등 종교.
4. 스트리머 채팅 투표 모드.
5. 신규 마을 구역.
6. 2~4인 루머 전쟁 모드.

## 4. 루머 전쟁 모드 설계 메모
- 2~4인.
- 각자 비밀 엔딩 목표 보유.
- 같은 마을 상태값을 공유한다.
- 각 플레이어가 동시에 소문을 제출하고 하루 단위로 정산한다.
- 소문 소유권을 기록한다.
- 충돌 이벤트가 멀티의 핵심 재미다.
- 먼저 자신의 엔딩을 달성한 플레이어가 승리한다.
- 스트리밍에서는 시청자가 중립 NPC 여론 역할을 할 수 있다.
