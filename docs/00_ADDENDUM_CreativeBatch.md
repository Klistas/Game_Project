## 2. 이 배치의 본질 — 전부 같은 게임이다

5개 모두 구조적으로 동일하다:

```
[대상 엔티티] + [부착물(스티커/이름표/법/포스터/부위)] → [태그 변경] → [규칙 해석기] → [행동/세계 변화]
```

즉 **"태그 기반 상호작용 엔진" 하나를 잘 만들면 5개 전부의 공통 기반이 된다.**

### 공통 코어: TagInteraction Framework (별도 패키지로 개발)
- `Entity` : 태그 집합(HashSet<TagSO>)을 가진 모든 사물/NPC
- `TagSO` : 속성 정의 (예: `Sleepy`, `Explosive`, `IsDoor`, `IsMayor`, `Currency`)
- `RuleSO` : `조건(태그 조합/이벤트) → 반응(행동/스폰/상태변화/대사)` — **상호작용은 전부 데이터**
- `RuleResolver` : 매 틱/이벤트마다 규칙 매칭. 우선순위/충돌 해소 정책 포함
- `ReactionLibrary` : 재사용 가능한 반응 프리미티브 30종 (잠들기, 폭발, 크기변경, 추종, 도주, 절하기, 거래, 경고표지 스폰...)

**핵심 설계 원칙 (조합 폭발 방지):**
1. N×M 개별 조합을 구현하지 않는다. `스티커 12개 × 오브젝트 20개 = 240조합`이 아니라 **태그 12개 × 반응 프리미티브 30개**로 환원한다.
2. 매칭 안 되는 조합은 "무반응"이 아니라 **범용 병맛 폴백**(물음표 이펙트, NPC 갸우뚱, 실패 대사)으로 처리 — 유저는 "모든 조합에 반응이 있다"고 느낀다.
3. 대사/반응 텍스트는 Claude API 배치 생성 → CSV 검수 → 정적 데이터로 굽는다 (런타임 AI 호출 금지, 비용/심의 리스크).

## 3. 운용 프로토콜 (01~03과 다른 점)

- **프로토타입 토너먼트 방식:** 04와 05는 코어가 80% 겹친다. TagInteraction Framework를 먼저 2주 만들고, 그 위에 04/05 프로토타입을 **각 1주씩** 얹어 재미를 직접 비교 → 이긴 쪽만 G1 진행. (07은 이긴 쪽의 확장 DLC/후속작 후보로 보류)
- **클립 우선 검증:** 이 장르는 "15초 클립이 웃긴가"가 위시리스트의 전부다. G0 통과 기준에 "플레이스홀더 그래픽 클립을 커뮤니티(X/디시 인디게임갤)에 올려 반응 확인"을 포함한다.
- **06(법)과 08(오려붙이기)은 착수 보류.** 06은 시각 즉시성 약함, 08은 물리/에셋 난이도 최고. 04 or 05가 성공해 프레임워크와 아트 파이프라인이 검증된 뒤 2호기로 승격한다.
- **통합 컨셉 "스티커 선동꾼"(04+07 합본)은 금지 목록.** 첫 버전에서 결과 공간을 키우는 것은 kill-by-default 원칙 위반. 04 성공 시 확장팩으로만 검토.

## 4. 시장 포지셔닝 근거 (공통)

- 이 배치의 레퍼런스 라인: Baba Is You(규칙 조작), Untitled Goose Game(병맛 목표), Scribblenauts(사물 소환), Wildfrost가 아닌 — **"규칙을 비트는 순간이 곧 콘텐츠"** 계열
- 강점: 클립 바이럴 잠재력 최상. 스팀에서 이 계열은 "Very Positive 이상 아니면 죽음"이므로 스코프 절제가 생명
- 약점: 01~03과 달리 **직접 비교 가능한 최근 매출 검증 사례가 약함** → 그래서 G0/G1 게이트를 더 엄격하게 운용 (아래)

### 강화된 게이트 (04~08 전용)
- **G0:** 프로토타입 클립 1개 이상이 외부 반응(합계 조회 1만 or "이거 뭐임 사고싶다" 류 댓글 20+)을 얻어야 통과
- **G1:** 스테이지 8개에서 테스터가 **의도하지 않은 해법**을 최소 3회 발견해야 통과 (창발이 없으면 이 장르는 죽은 것)
- **G2:** 위시리스트 기준 1,000/4주 (클립 장르는 초기 견인이 없으면 출시 때도 없다)
