# GDD — 화투 로그 (가칭: HWATU ROGUE)

> 장르: 덱빌딩 로그라이트 | 가격: ₩11,000 / $7.99 | 기간: 4~6개월 | 플랫폼: Steam(PC) → 모바일 이식 검토
> 엔진: Unity 6, 2D URP | 세로형 아님, 16:9 | 언어: KO/EN (+JP 검토)

## 0. 원 센텐스 피치

**"발라트로의 화투 버전 — 고스톱 족보로 점수를 터뜨리고, 저승 시장에서 부적과 변조 패로 덱을 개조해 저승 12관문을 돌파하는 로그라이트."**

### 시장 근거
- "익숙한 전통 카드 규칙 × 로그라이트 변형"은 발라트로($1억+), Gambonanza(솔로 개발, 2주 20만 장)로 연속 검증된 공식
- 화투는 글로벌 시장에서 **시각적으로 완전히 새로운 소재** (비주얼 차별화 = 캡슐 이미지 클릭률)
- K-소재 게임(산나비, 안녕서울)의 글로벌 경쟁력 상승 흐름과 합치
- 준헌님 강점(시스템/밸런스 설계, 알고리즘)과 최고 궁합

### 리스크
- 3개 기획 중 스코프 최대 → **반드시 02, 03 출시 경험 후 착수 권장**
- 고스톱 규칙의 해외 진입장벽 → "고스톱을 그대로"가 아니라 "족보 기반 점수 시스템"으로 단순화하여 해결 (발라트로가 포커 그 자체가 아니듯)

## 1. 코어 루프

```
[런 시작] 기본 덱 20장 + 부적 0개
 → 관문 진입: 목표 점수 제시 (예: 3,000점)
 → 라운드: 손패 8장 중 최대 5장 제출 → 족보 판정 → 점수 = 기본점수 × 배수
 → 제출 기회 4회 + 버리기 3회 안에 목표 달성
 → 성공: 엽전 획득 → 저승 시장 (패 구매/제거/강화, 부적 구매)
 → 12관문(보스 3회) 돌파 시 승리 → 다음 난이도 해금
 → 실패: 런 종료, 메타 화폐(넋)로 영구 해금
```

**세션 길이:** 1런 25~40분. "한 판만 더" 구조.

## 2. 시스템 설계

### 2.1 족보 시스템 (점수 엔진)
- 기본 족보: 광(光) 모으기, 띠, 피, 끗, 같은 월 3장(폭탄), 5장 연속 월(스트레이트) 등 12종
- `기본점수 × 배수` 구조. 족보마다 (chips, mult) 성장 테이블 보유 — 같은 족보 반복 사용 시 레벨업
- 판정 우선순위/중첩 규칙은 `ScorePipeline` 클래스에서 단계별 이벤트로 처리 (부적이 각 단계에 훅킹)

### 2.2 카드 (화투 48장 + 변조 패)
- 기본 48장: 12개 월 × 4장 (광/열끗/띠/피 속성)
- 변조 패(에디션): 금박(점수+), 야광(배수+), 찢어진 패(제출 후 소멸, 강력), 뒤집힌 패(랜덤 월 취급) 등 8종
- 시장에서 패 추가/제거/변조 가능 — 덱 압축(제거) 전략이 핵심 깊이

### 2.3 부적 시스템 (조커 포지션, 콘텐츠의 심장)
- 슬롯 5개, 목표 종수: MVP 30종 → 출시 80종 → 업데이트 120종
- 설계 축: ①특정 족보 강화 ②특정 월/속성 시너지 ③경제(엽전) ④리스크-리워드(패 소멸, 체력 소모) ⑤규칙 파괴(손패+2, 제출 기회+1)
- 데이터: `CharmSO : ScriptableObject` — id, 희귀도, 트리거(이벤트 enum), 효과(파라미터화), 가격, 로컬라이즈 키

### 2.4 관문 & 보스
- 12관문 = 12개월 테마. 3/7/12관문 보스(저승사자)는 방해 규칙 부여 (예: "비(12월) 패 사용 불가", "버리기 금지")
- 보스 방해 규칙 목표 15종

### 2.5 메타 진행
- 넋(메타 화폐)으로 시작 덱 프리셋, 신규 부적 풀, 난이도(업화 1~8단계) 해금
- 도전과제 20개 (족보 관련 10 + 런 클리어 조건 10)

## 3. 아트/사운드 방향

- **비주얼 키워드:** 한국 무속 + 네온. 검은 배경, 화투의 원색(빨강/검정/금)을 네온으로 재해석. "어둠 속에서 패가 빛나는" 캡슐 이미지
- 화투 패 48장 리디자인이 아트의 80% — Ludo.ai로 스타일 탐색 → 최종은 일관성 위해 수작업 보정 필수
- 점수 터질 때 연출(카운트업, 화면 흔들림, 패 발광)에 아트 예산의 30% — **이 게임의 클립 = 점수 폭발 순간**
- BGM: 국악 샘플 × 로파이/신스 3~5트랙 (외주 or 라이선스)

## 5. 개발 로드맵 (Claude Code Phase)

### Phase 0 — 프로젝트 셋업 (세션 1회)
- [ ] Unity 6 2D URP 프로젝트, Git 초기화, 폴더 규약(`Scripts/Core, Gameplay, Data, UI`)
- [ ] EventBus, ServiceLocator, SaveSystem(JSON) 골격 이식
- [ ] `CardSO`, `CharmSO`, `HandRankSO` ScriptableObject 스키마 정의 + 에디터에서 CSV 임포트 툴
- **DoD:** 48장 카드 데이터가 SO로 로드되고 콘솔에 덱 셔플/드로우 출력

### Phase 1 — 점수 엔진 (세션 2~3회) ★가장 중요
- [ ] `HandEvaluator`: 제출 5장 → 성립 족보 전체 판정 (유닛테스트 30케이스 이상 필수)
- [ ] `ScorePipeline`: 기본점수 → 패 보너스 → 족보 배수 → 부적 훅 순서의 이벤트 체인
- [ ] 부적 효과 프레임워크: 트리거 enum(OnScoreCard, OnHandPlayed, OnDiscard, OnShopEnter...) + 파라미터화된 효과
- **DoD:** 유닛테스트 전부 통과. 부적 3종이 데이터만으로(코드 수정 없이) 동작
- **Claude Code 지시:** "점수 계산은 절대 UI와 결합하지 말 것. 순수 C# 클래스로 유지하고 테스트 우선 작성"

### Phase 2 — 런 루프 (세션 2회)
- [ ] 관문 진행 상태머신 (Map → Round → Shop → GameOver/Victory)
- [ ] 손패 UI: 드로우/선택/제출/버리기, 남은 기회 표시
- [ ] 시장: 패 구매/제거/부적 구매, 리롤
- **DoD:** 플레이스홀더 아트로 3관문 1런 완주 가능 → **G0 게이트 판정**

### Phase 3 — 버티컬 슬라이스 (세션 3~4회)
